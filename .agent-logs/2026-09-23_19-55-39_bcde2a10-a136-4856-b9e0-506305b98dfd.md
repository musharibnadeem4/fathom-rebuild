**Three things about the sync approach you should know before building on it:**

1. **Highlight tracking uses `requestAnimationFrame`, not `timeupdate`, but only re-renders on index change.** `timeupdate` is spec'd to fire as infrequently as every ~250ms, which reads as laggy against audio. The rAF loop polls every frame but only calls `setState` when the *active utterance index* actually changes — `currentTime` itself never touches React state. This is why it'll stay smooth even on a dense hour-long transcript with 1000+ utterances: most frames land inside the same utterance and cause zero re-renders. Finding the active index is a binary search over sorted `startMs`, so it stays cheap regardless of transcript length.

2. **"Active" persists through silence gaps.** Active = the *last* utterance whose `startMs` has passed, not a strict `startMs ≤ t < endMs` window. During a pause between turns, the previous line stays highlighted rather than flickering off. This was a deliberate call, not an oversight — flag it if you want gap behavior to be "nothing highlighted" instead.

3. **The transcript's scroll-margin is hardcoded to the current player's height, and that's fragile.** `scroll-mt-[328px]` on each line exists so `scrollIntoView` doesn't tuck the active line behind the sticky player+tabs block — I actually hit this bug live during verification (first tried 268px, measured the real sticky block height, still got it wrong the first time by forgetting the `top-16` offset, then fixed it and reconfirmed with a 20px clear gap).
