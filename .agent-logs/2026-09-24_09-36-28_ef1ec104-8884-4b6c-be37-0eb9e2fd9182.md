Everything is built and verified working end-to-end against the real APIs. Here's what changed:

**New upload flow (`/meetings/new`)**
- File + title form, client-side duration check via a hidden `<video>` element (cheap, no upload needed), 12-minute cap enforced before anything is sent.
- On submit: `POST /api/meetings` creates the meeting row as `status: "processing"` and returns a Supabase **signed upload URL**; the browser then PUTs the file straight to Supabase Storage; then `POST /api/meetings/[id]/ingest` kicks off transcription + Gemini analysis and the browser redirects immediately to `/meetings/[id]`.
- The meeting detail page now branches on `status`: processing → spinner that polls `/api/meetings/[id]/status` every 4s and calls `router.refresh()` once ready (no manual reload); failed → clear error state with a link back to `/meetings/new`. Same status badges now show up on the meetings list cards too.

**Shared pipeline** — `scripts/seed.ts` and the new ingest route both now call into `src/lib/pipeline.ts` (upload/transcribe/analyze/write, one copy of the logic, zero duplication).

**Verified locally**: ran the real flow against your actual Supabase/AssemblyAI/Gemini — created a meeting, uploaded an 8-min mp3, watched it flip `processing → ready` in ~35s with real transcript/summary/chapters/action items written to the DB, and confirmed the detail page renders it. Also confirmed the 12-minute cap correctly rejects a 59-minute file server-side (via a header-only duration probe, not a full download).

**Three things to double-check on Vercel specifically:**

1. **Request body size** — Vercel serverless functions cap inbound request bodies at a few MB, which a 12-minute recording would blow past instantly. I avoided this entirely: the file goes browser → Supabase Storage directly via a signed URL, never through your Next.js function, so this limit doesn't apply.
2. **Execution time** — the ingest route uses `after()` to keep transcribing/analyzing after the response is sent, with `maxDuration = 300`. **This needs at minimum a Vercel Pro plan** — Hobby hard-caps function duration at 60s regardless of `maxDuration`, and a few minutes of AssemblyAI + Gemini work won't fit in that.
3. **New env var** — `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` is now actually used (by the browser upload) for the first time; it was in your `.env.local` but unused before. Since it's `NEXT_PUBLIC_`-prefixed, Next.js inlines it **at build time**, so make sure it's set in Vercel's env vars before the build runs, not just at runtime — the same class of gotcha you hit with `DATABASE_URL`.
